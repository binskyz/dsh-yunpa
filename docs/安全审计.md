# dsh-yunpa 安全审计（v0.6，2026-11-07）

范围：凭据流 / 日志与残留 / profile 泄漏路径 / 接口暴露 / 供应链。结论：**5 个 P0 必须先修，才能发 GitHub**。

## P0（阻断发布）

| # | 问题 | 证据 | 影响 | 修法 |
|---|---|---|---|---|
| 1 | **裸主密钥与密文同目录** | `~/.dsh/private/yunpa/key.bin`（32B）与 `vault.bin` 并列 | DPAPI 包裹形同虚设：拿到目录即解开全部密码 | 删 `key.bin`；只走 `wrappedKey`；v1 库迁移后立刻删除 |
| 2 | **Edge 凭据副本留在磁盘** | `pw-profile/Default/Login Data`、`pw-profile/Local State`（含 app_bound_encrypted_key） | 等于把 Edge 密码库+解密密钥复制一份放在可读目录 | 迁移结束即删 `pw-profile`；改成用后即焚（`finally` 清理） |
| 3 | **本地 API 无鉴权 + `Access-Control-Allow-Origin: *`** | `api.js` 对 `/status`、`/vault`、`/edge`、`/action` 全开 | 本机任意网页可读账号列表、触发开浏览器/删凭据 | 去掉 `*`，只允许同源；加 per-run token（宿主注入，页面从 `__DSH_BOOT__` 取） |
| 4 | **`taskkill /IM chrome.exe /F`** | `check-all.mjs` 隐私回归项 | 用户以后装了正式 Chrome，跑自检会强杀 | 只杀自己 profile 的进程（按命令行匹配 user-data-dir） |
| 5 | **更新无完整性校验** | `upgrade.mjs` 直连 Google 存储，`Expand-Archive` 后即用 | 中间人/投毒镜像可换进任意二进制 | 记录官方 SHA256（CFT 提供 `checksums` 或缺省用 HTTPS+版本内嵌哈希），校验不过拒绝替换 |

## P1（发布前一并处理）

| # | 问题 | 说明 |
|---|---|---|
| 6 | 网络调试日志残留 | `netlog*.json`（2.3MB URL 记录）、`netlog-profile/`、`pw-profile/`、`eg-*`/`nl-*` 测试 profile 全在数据目录，需 `.gitignore` + 启动时清理 |
| 7 | 截图留存 | `.dsh-login/*.png` 可能含登录后页面；加保留上限（默认 7 天/20 张） |
| 8 | 错误信息回显 | 工具把 `String(e.message)` 直接回给模型，抓取失败时可能带完整 URL（含 token 参数）；脱敏 query |
| 9 | 凭据列表未打码（工具层） | `auth_vault list` 回完整用户名；API 层已打码，工具层建议一致 |
| 10 | profile cookie 为 v10 | 同用户任意进程可解（已在隐私报告记录）；发版前要么接受并在 README 写明，要么提供 `wipeProfile` 默认开 |

## P2（可延后）
- CLI 无输入校验（`--site` 任意串会拼进 URL）；`spawn` 参数已用数组无注入面，但站点白名单建议收敛。
- 无审计日志（谁在何时读了哪站 cookie）——发布版可作为特性。
- Windows-only（DPAPI/icacls/PowerShell）：README 明确标注，非 Windows 走降级分支或直接拒绝。

## 结论
P0 全修 + P1 前三项 + `.gitignore`/README 声明，才达到“可公开”。P0 修完预计不影响现有 11 项自检。
