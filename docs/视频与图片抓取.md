# 视频与图片抓取方案（B站 / 抖音 / YouTube / 通用）

这份文档只讲**怎么拿到媒体文件的直链并落盘**，不讲怎么绕过会员权限或付费墙。

## 三条技术路线，按稳定性排序

| 路线 | 原理 | 适用 | 风险 |
|---|---|---|---|
| **A. 页面 JSON 提取** | 受控浏览器打开页面，从 `window.__INITIAL_STATE__` / `_ROUTER_DATA` 里读结构化数据 | B站、抖音、小红书、微博 | 低：签名由页面自己的 JS 算好，我们只读结果 |
| **B. 官方/半公开 API** | 直接请求 JSON 接口，带 `Referer` + 已存 cookie | B站（playurl）、Pixiv | 中：需要 wbi 签名、风控 (`-352`)，接口会变 |
| **C. 成熟工具调用** | 交给 `yt-dlp` / `gallery-dl` 处理 | YouTube、Twitter、Instagram 等 1800+ 站点 | 低：维护成本在别人那边；需要本机装 Python 或独立二进制 |

**默认选 A**——受控浏览器里已经有登录态，页面能正常加载就说明风控已过，我们只做「读」这一步。

## B站（bilibili）

### 视频

```bash
# 1) 从页面取元信息（在受控浏览器里执行）
window.__INITIAL_STATE__.videoData   # → bvid / cid / 标题 / UP 主 / 分P 列表

# 2) 取播放地址（需要 Referer + SESSDATA cookie）
GET https://api.bilibili.com/x/player/playurl
    ?bvid=BV1xx411c7mD&cid=123456&qn=80&fnval=16
Referer: https://www.bilibili.com/
Cookie:  SESSDATA=...; bili_jct=...
# → data.dash.video[] / data.dash.audio[]（分离的音视频流，按 id 分辨清晰度）
```

- `fnval=16` 才返回 DASH；`qn` 只对非 DASH 生效
- **高清（1080P+ / 4K）必须有大会员 cookie**，否则降到 480P/720P
- 音视频分离，要用 `ffmpeg -i video.m4s -i audio.m4s -c copy out.mp4`
- 常见错误：`-352` 风控（缺 wbi 签名或 UA/Referer 不对）、`-404` cid 过期

### 图片（动态 / 相册）

```bash
GET https://api.vc.bilibili.com/dynamic_svr/v1/dynamic_svr/space_history?host_uid=<uid>
Referer: https://space.bilibili.com/
# → data.cards[].card（字符串，再 JSON.parse）→ item.pictures[].img_src
```

图片直链带 `@` 后缀可要原图：`https://i0.hdslb.com/bfs/...jpg` 去掉 `@xxx.webp` 后缀即原图。

## 抖音（douyin）

抖音的接口签名（`a_bogus` / `X-Bogus`）周级别变化，**不要逆**。走路线 A：

```js
// 受控浏览器打开分享链接后，页面里有完整数据
window._ROUTER_DATA.loaderData['video_(id)/page'].videoInfoRes.item_list[0]
```

- 视频直链：`item.video.play_addr.url_list[]`（**无水印**是 `play_addr`，带水印是 `download_addr`）
- 图集：`item.images[].url_list[]`
- 音乐：`item.music.play_url.url_list[]`
- 分享短链要先跟一次重定向拿 `aweme_id`：`https://v.douyin.com/xxx/` → 302
- 直链有防盗链：下载时带 `Referer: https://www.douyin.com/` 和浏览器 UA
- 登录态（cookie）能显著降低「页面只给降级资源」的概率

## YouTube

不建议自己拼 InnerTube 请求（key 与 `visitorData` 都要现取）。用路线 C：

```bash
yt-dlp -f "bv*+ba/b" --merge-output-format mp4 "https://www.youtube.com/watch?v=ID"
yt-dlp --write-thumbnail --skip-download "URL"     # 只取封面
```

- 缩略图直链无需任何鉴权：`https://i.ytimg.com/vi/<id>/maxresdefault.jpg`（1080P 封面），`hqdefault.jpg` 一定存在
- 需要登录的（会员/私享）用 `--cookies-from-browser edge` 复用本机浏览器的登录态

## 通用落地骨架（在插件里怎么接）

```js
// 1) 受控浏览器打开，等页面数据就绪
await goto(url)
await waitFor(() => document.querySelector('#app') !== null)

// 2) 在页面上下文里取结构化数据（签名、风控都由页面自己处理）
const data = await evaluate(`JSON.stringify(window.__INITIAL_STATE__)`)

// 3) 下载媒体（带 Referer + 已存 cookie，走 fetchWith）
const buf = await fetchWith(site, mediaUrl, cookies, { referer })

// 4) 落盘 + 合并（合并需要本机 ffmpeg，可选）
writeFileSync(out, buf)
```

要点：

- **媒体下载不要用 fetch 的内存流**：几十分钟的视频会撑爆内存。用 `fetch` 拿 `response.body` 管道写文件。
- **并发限 3**：B站/抖音对同一 IP 的并发下载敏感。
- **文件名用 `id + 标题前 30 字`**，不要用标题原文（含 `/ \ : * ?` 会炸 Windows 路径）。
- **每次下载写一行 `audit.jsonl`**（url / 字节数 / 结果），出问题能回溯。

## 不做的部分

- 不绕会员/付费墙：没有有效 cookie 就只拿公开清晰度。
- 不批量爬个人主页：单次任务限制在「一个链接 → 一份媒体」，避免变成爬虫。
- 不破 DRM（Widevine 等）。

## 优先级建议

1. **B站**（接口稳定、JSON 结构清晰）—— 可以做到 `media_probe` + `media_fetch` 两个工具
2. **抖音**（页面 JSON 提取，受控浏览器已能处理签名）
3. **YouTube**（直接建议用户装 `yt-dlp`，插件只做「下载完成后的整理」）
