# 崩溃日志与还原（硬规则）

## 规则
1. **任何崩溃都必须留痕**：前端 / 宿主 / 工具层，一律写 `~/.dsh/private/yunpa/crash.jsonl`；动作审计另写 `audit.jsonl`。
2. **任何崩溃都必须能还原**：最小还原 = 注释 `cordis.patch.yml` 里本插件那 4 行 → 重启。

## 日志在哪
| 文件 | 内容 | 查看 |
|---|---|---|
| `crash.jsonl` | `{ts, source, message, stack}`；source = `client` / `host:uncaughtException` / `host:unhandledRejection` / `boot` | `GET /api/yunpa/crashes`（最近 20 条）或直接读文件 |
| `audit.jsonl` | 动作流水（login/capture/fetch/forget…，无凭据） | `GET /api/yunpa/audit` |
| `%APPDATA%\@deepseek-ai\dsh-desktop\logs\crash-*.log` | **DSH 自己的**启动崩溃记录（含插件名与报错） | 直接打开 |

两端对照：DSH 说“某 entry did not activate”，就去 `crash.jsonl` 找同时间戳的 `client` 条目，里面有 JS 堆栈。

## 客户端侧实现
- `client.js` 导出 `inject = ['slots','locale']`（缺它 → slots 未就绪 → 整站启动失败）
- `apply()` 整体 try/catch，失败只上报不抛
- 全局 `error` / `unhandledrejection` 钩子 → POST `/api/yunpa/client-error`

## 宿主侧实现
- `installCrashHandlers()`：`uncaughtException` / `unhandledRejection` → `crash('host:*')`
- 启动时写一条 `boot` 记录，用来确认"这一版跑起来过"

## 还原
```bash
cd ~/.dsh/plugins-local/dsh-yunpa
node recover.mjs --status    # 先看现在是启用还是禁用（只读）
node recover.mjs             # 注释掉 cordis.yml 与 cordis.patch.yml 里的挂载（各自备份）
node recover.mjs --purge     # 再把 node_modules/dsh-yunpa 改名禁用（最彻底）
node recover.mjs --restore   # 反过来：从最新 .bak-recover-* 恢复
```
之后重启 DSH。数据目录 `~/.dsh/private/yunpa` 不动（凭据、日志都保留）。
`recover.mjs` 故意不 import `core.js`：插件坏掉的时候，还原工具不能跟着一起坏。

## 本次案例（2026-11-07 22:21）
```
crash-2026-11-07T14-21-05-964Z-web-boot.log
Error: web boot: 1 entry did not activate
dsh-yunpa: failed
```
根因：`client.js` 漏导出 `inject` → `ctx.slots` 未就绪 → apply 抛错 → 整个 web boot 失败；
DSH 自动把 patch 里那 4 行注释掉来自保。修复：补 `inject` + apply try/catch + 崩溃上报。
