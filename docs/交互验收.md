# 交互验收单（重启 DSH 后照做，每步一句）

## 0. 前置
- 现在跑的是旧版本；**重启 DSH**（关窗口再打开），会话会重新开始。

## 1. 自动验收（不用点任何东西）
在新会话里说「跑验收」，或手动：

```bash
node ~/.dsh/plugins-local/dsh-yunpa/after-restart.mjs
```
期望全部 ✅（含 `HeadlessChrome/157.0.8103.38`、`cordis.yml 已加载`、`profile 内插件版本 v0.10.0 / 本源 v0.10.0`）。

## 2. 设置页
设置 → **云爬**（没有就是没加载，回来找我）。
- 概览：受控浏览器「未启动」、凭据库 1 组、登录态 0
- 点「启动浏览器」→ 不应弹窗（无头），状态变「运行中 · 9333」
- 点「跑自检」→ 三项通过
- 点「关闭浏览器」→ 回到未启动

## 3. 链路测试（不需要账号）
对 agent 说：**用登录态抓 https://www.alicesw.com/**
- 期望返回 200 + 含「示例书目」
- 备注：该站不需要 cookie，`auth_fetch` 会提示 no_cookie；改用 `browser_open` + `browser_get_text` 也可，二选一

## 4. 真实登录（要账号）
对 agent 说：**登录贴吧**（会弹窗，你自己登 + 过验证码）→ 登完说「抓登录态」
- 期望 `auth_capture` 返回 cookies>0 且 probe.loggedIn=true
- 想省事：`auth_capture {wipeProfile:true}` 抓完把 profile 清掉

## 5. 验收审计
```bash
type "%USERPROFILE%\.dsh\private\yunpa\audit.jsonl"
```
应看到 `login` / `capture` / `fetch` 等条目，**不含任何密码或 cookie 值**。

## 失败对照
| 现象 | 原因 | 处理 |
|---|---|---|
| 设置页没有「云爬」 | client 半身没加载 | 把 `dsh-yunpa` 加进 profile 的 `dsh.profile.bundles` 后重启 |
| 点启动浏览器弹窗 | 走了 visible 模式 | 属正常（仅登录/自动填充会弹）；其他动作应无窗口 |
| 抓取 403 | 没 cookie 或登录失效 | 重新 `auth_login` → `auth_capture` |
